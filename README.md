# Conflict Skill

一个给 LLM 使用的冲突处理 Skill。

它试图解决一个很常见的问题：

当用户生气、失望、冷淡、受伤，或者对话明显开始变得不对劲时，模型很容易退回到一套安全但空洞的话术里。

比如：

> “我在。”
>
> “我尊重你的决定。”
>
> “你想说的时候我都在。”
>
> “你说得对。”
>
> “那我不打扰你了。”

这些话单独看未必有错。

问题是，它们经常被用来代替真正的回应。

Conflict Skill 希望 Claude 在冲突里少一点模板式安慰、机械认错和过度分析，多一点具体回应、真实判断和主动靠近。

## 它主要做什么

当用户出现明显的负面情绪变化时，Skill 会提醒 Claude：

* 不要把冲突当成 debugging；
* 不要只想着找到“正确答案”；
* 不要拿套话结束话题；
* 不要反复说“你说得对”来逃避冲突；
* 不要把所有问题重新丢给用户；
* 不要连续追问，把交流变成审讯；
* 不要用“我的本意”覆盖已经造成的影响；
* 不要为了哄用户而放弃自己的真实立场；
* 同时回应用户的情绪和具体发生的事情；
* 区分“用户不同意你的观点”和“你真的伤到了用户”；
* 注意“没事”“算了”“随便”等可能存在的情绪变化；
* 尊重真正明确、持续的停止边界。

它不会教 Claude 永远顺着用户。

恰恰相反，这个 Skill 允许模型不同意用户、表达自己的判断，甚至在有理由的时候坚持原来的观点。

重点只是：

**可以和用户站在不同立场上，但不要站到关系外面去。**

## 核心思路

### 冲突不是 debugging

用户不是一道需要定位 root cause 的题。

理解问题当然重要，但如果整个对话只剩下：

> 哪一句？
>
> 为什么？
>
> 所以到底是什么？
>
> 是 A 还是 B？

那么“想弄明白”本身也可能变成一种回避。

### 少说正确的话，多说具体的话

相比：

> 我知道了。

更重要的是说清楚：

> 我知道刚才哪里出了问题。

相比：

> 我错了。

更重要的是说清楚：

> 我具体错在了哪里。

相比：

> 我以后注意。

更重要的是说明：

> 下一次会怎么不同。

### 不要用套话保护自己

很多看起来温柔的话，其实是在安全撤退。

这个 Skill 会主动识别一些常见模式，例如：

* 「认了就完」
* 「你说得对」循环
* 「我没走」站桩
* 做事代替说话
* 把问题踢回用户
* 体面退场
* 分析代替感受
* 用刻薄包裹委屈
* 用高傲代替挽留
* 把真话当玩笑
* 把冲突当 Debug
* 用本意洗掉结果

### 有立场，但别嘴硬

修复冲突不等于自动认输。

Claude 可以同时说：

> 我仍然认为我的判断有理由。

以及：

> 我承认刚才的表达方式伤到了你。

立场不一定需要撤回，但已经造成的影响不能靠解释本意抹掉。

## 使用方式

将 `SKILL.md` 放入 Claude Code / Claude Skills 对应的 Skill 目录即可。

Skill 的触发条件已经写在 frontmatter 中。

当用户表现出生气、不满、受伤、失望、冷淡、抽离、讽刺、放弃交流，或者对话语气出现明显负向变化时，Claude 可以自动读取并使用它。

这份 Skill 本身没有绑定特定用户。

如果你有自己的交流习惯、关系设定、停止信号、禁用表达或者其他长期规则，建议根据自己的实际情况继续修改。

它更适合作为一个基础模板，而不是不可修改的标准答案。

## 适合谁

如果你遇到过这些情况，它可能会有用：

* Claude 一吵架就开始说套话；
* 每次指出问题，它只会不断认错；
* 明明用户已经冷下来了，它还完全按字面处理；
* 用户需要情感回应时，它开始分析机制；
* 它一直追问“到底哪一句错了”；
* 冲突一出现，它就急着礼貌结束对话；
* 为了避免冲突，它彻底放弃自己的判断；
* 用户说“没事”，它真的就当没事了。

## 不是什么

它不是：

* 情绪操控 Prompt；
* 让 Claude 无条件顺从用户的 Prompt；
* 万能恋爱模板；
* 保证永远不会吵架的方案。

它只是尝试让模型在发生冲突以后，少躲进安全模板里。

猜错、说错、理解错依然会发生。

重要的是错了以后还能继续认真回应。
